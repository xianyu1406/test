# 运动识别基线与验证边界

本版是可回放的保守规则，参数标记为**待真机校准基线**。自动测试只证明给定传感器序列的算法行为，不能证明真实步行识别准确率、本人清醒或所有摇晃/车辆场景都能被排除。

## 真实采集路径

`AndroidMotionSource` 使用 `SensorManager`，优先 `TYPE_STEP_DETECTOR`，否则使用 `TYPE_STEP_COUNTER` 当前会话的增量；同时采集加速度、陀螺仪以及重力（缺少重力时选旋转向量）。系统事件的纳秒时间转换为开机单调毫秒。完整模式需要这些能力和 Android 10 以上身体活动权限。权限、注册失败、数据中断均返回具体技术原因。

源由活动提醒服务持有，停止时取消监听和工作线程，不做全天采集。适配器没有生产模拟成功入口。只在内存保留约 30 秒的数据用于判断，不写原始传感器日志。前台服务资格、通知和唤醒锁由提醒服务处理，传感器线程本身不构成后台运行保证。

缺少陀螺仪/方向硬件时不得自动降级为完整验证。算法提供 `REDUCED_SENSORS` 显式选择接口（仍要求系统计步及加速度）；当前用户流程可明确退回普通档。没有计步硬件时直接说明限制并允许普通档，不用加速度阈值冒充完整步行验证。

## 判断规则

| 条件 | 初始值/策略 |
| --- | --- |
| 新片段 | 连续时间至少 15 秒，至少 10 个新步伐 |
| 步伐间隔 | 250–2200 毫秒，间隔变异系数不超过 0.55 |
| 加速度 | 完整模式沿实测重力方向（或旋转向量推导的重力轴）投影，去除重力后的波动 RMS 0.18–4.5 m/s²；较弱模式使用总加速度幅度 |
| 节律一致性 | 加速度局部峰数约为系统步数的 0.6–1.8 倍，过密振动不通过 |
| 陀螺仪 | 检查新鲜样本和过大旋转，**不要求大幅旋转** |
| 连续采集 | 首先需要至少 2 秒正常采集；加速度间隔超过 400 毫秒清空待判步行片段 |
| 断流 | 必需传感器超过 2 秒没有新样本为数据不足 |
| 计步计数器 | 首次总数仅建基线；总数回退重新建基线；延迟超过 2 秒或突增批次不推算历史步伐 |
| 去重 | 每个片段有源会话 UUID + 序号；已通过步伐立即消费，重复/逆序回调不产生新片段 |

三态分别为有效步行、采集正常但未识别步行、数据不足/不可用。静止时持续收到正常的零/微小传感器数据属于第二态；没有回调属于第三态。静止、短暂拿起、翻身或数次零碎晃动不能单独满足时间和节律条件。

每秒向状态机报告一次采集情况，即使没有新传感器事件也会检查断流。状态机只累加连续正常报告覆盖的时长，并在运动超时点检查足够覆盖；数据不足不能伪装成行为失败。片段只有一次完成时间，并由状态机归属到一个观察窗口。保存/恢复的会话状态与传感器短期缓存分离；进程重建须重新获得新证据。

## 尚不能推断的事项

手机传感器不能确认手机使用者本人正在行走，手机放桌面时也无法确认旁边的人已起床。持续、有节律的人工晃动可能与某些步行信号相似；系统计步器可能把车辆振动算作步数。本基线降低这些误判机会，但没有实机数据，不能承诺消除误判。扶稳手机、缓慢步行和特定口袋位置也可能漏判；不以放宽规则或隐蔽模拟输入掩盖限制。

真机验收需记录机型、Android 版本、参数、场景、预期、实际三态、片段起止/原因及证据位置。至少覆盖：自然步行/慢走、手持/裤袋/衣袋/扶稳、原地静止/桌面、翻身/拿起/零碎晃动/连续晃动、车辆振动、锁屏/切应用/省电/Doze、权限撤销、传感器缺失及回调断流。只记录最小状态与原因；需要原始录制时必须另行提供用户主动开启、明确告知且可停止的工具，当前应用不自动录制。
